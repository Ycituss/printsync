# PrintSync · 3D 打印本地进度工作台

> 局域网内统一管理多台拓竹（Bambu Lab）3D 打印机的本地进度看板 —— **零云端、零令牌、可断网运行**。

PrintSync 是一个单机的 3D 打印文件进度管理工具，一边通过局域网 MQTT 实时订阅多台拓竹打印机的状态，一边提供一块看板式仪表盘，用于人工跟踪每个打印文件的流转进度（待打印 → 打印中 → 待摆盘填表 → 已完成 → 归档）。

- 🖥️ **纯本地**：所有数据留在本机，不依赖任何云服务、不需要注册账号、不申请任何 API 令牌。
- 🔌 **局域网模式**：直连打印机 MQTT（端口 8883，TLS），无需 Bambu 云端账号。
- 📊 **看板管理**：2×3 看板 + 独立归档区，支持拖拽改状态、一键推进、搜索高亮。
- 📣 **企业微信推送**：打印完成 / 即将完成 / 出错自动提醒（可选）；换料期间自动静默，不被刷屏。
- 🔐 **IP 访问控制**：可配置白名单 IP 才可编辑，其余仅可查看。

## 功能特性

| 类别 | 说明 |
| --- | --- |
| 打印机监控 | 实时订阅每台打印机 MQTT，解析 `空闲 / 打印中 / 暂停 / 已完成 / 失败` 及当前文件名、进度、剩余分钟、喷嘴温度、错误码 |
| 进度看板 | 2×3 网格看板，各状态独立列、独立高度、超量自动内部滚动 |
| 状态流转 | 卡片上一键 `▶` 推进下一状态；支持拖拽跨列改状态 |
| 归档区 | 「已完成 → 归档」为终态，归档文件独立侧栏展示，点开弹窗看详情，不入看板 |
| 搜索 | 按文件名 / 备注 / 机器实时过滤；命中 1 个时显示全部并高亮跳动提示 |
| 数据备份 | 导出 / 导入 JSON 备份；后端写盘自动保留最近 **5** 份历史（`files.json.bak1~5`） |
| 快照恢复 | 侧栏「数据快照」列出自动备份，点击可查看**和主界面一致的只读预览**，一键恢复到任意历史版本（恢复前当前数据会再次留档，可反复回退） |
| 通知 | 企业微信群机器人 webhook：完成通知、即将完成（≤10 分钟，带防抖）、出错告警；**换料期间自动静默** |
| 鉴权 | IP 白名单，非白名单 IP 只读（写操作返回 403） |

## 系统架构

```
               局域网 (LAN)
  ┌──────────────┐         MQTT/TLS :8883
  │ 拓竹打印机 ×6  │ ────────subscribe────────┐
  │ (Bambu Lab)   │  device/{serial}/report   │
  └──────────────┘                           │
                                             ▼
                              ┌────────────────────────────┐
  浏览器 (同局域网任意设备)    │        app.py (本机常开)       │
  ┌──────────────┐            │  ┌──────────────────────────┐│
  │ dashboard.html │ ──HTTP──▶ │  │ ThreadingHTTPServer       ││
  │  (看板前端)   │ ◀──JSON── │  │  · /api/* 读写文件进度     ││
  └──────────────┘            │  │  · 托管 dashboard.html     ││
                              │  ├──────────────────────────┤│
                              │  │ MQTT 客户端 × N (每机 1 个) ││
                              │  │  · pushall 周期刷新          ││
                              │  │  · 解析状态 + 企业微信推送   ││
                              │  └──────────────────────────┘│
                              │         │              │       │
                              │         ▼              ▼       │
                              │   data/files.json   logs/      │
                              └────────────────────────────┘
```

- **后端**：单文件 `app.py`，基于标准库 `http.server.ThreadingHTTPServer` + `paho-mqtt`，无 Web 框架依赖。
- **前端**：单文件 `dashboard.html`，原生 HTML/CSS/JS，由后端直接托管，无需构建。
- **数据**：`data/files.json`（人工维护的文件进度）；打印机实时状态只在内存中。

## 环境要求

- Python **3.10+**（已测试 3.13）
- 仅一个第三方依赖：`paho-mqtt`
- 运行机与打印机在**同一局域网**，且能通过 `8883` 端口访问打印机

```bash
pip install paho-mqtt
```

## 首次初始化配置

真实打印机参数（序列号、Access Code）属于私密信息，**`config.json` 已被加入 `.gitignore`，不会提交到仓库**。仓库内置 `config.example.json` 作为模板，克隆后需先生成自己的 `config.json`：

```bash
# 复制模板（Windows 用 copy）
cp config.example.json config.json
```

然后编辑 `config.json`，把每台打印机的 `ip / serial / access_code` 替换为你自己的真实值（详见下方「配置说明」）。**`config.example.json` 保持不动**，作为团队共享的模板随仓库提交。

> 若 `config.json` 不存在，服务启动时会因找不到配置而直接退出。

## 快速开始

### 方式一：一键启动（Windows）

直接双击 `run.bat`，脚本会自动检测并安装缺失的 `paho-mqtt`，随后启动服务。

启动后控制台会打印两个地址：

```
  本机:    http://127.0.0.1:8000
  局域网:  http://192.168.1.x:8000
```

用浏览器打开「局域网」地址即可（同网手机 / 平板 / 其他电脑相同地址）。

### 方式二：命令行启动（跨平台）

```bash
# 默认配置
python app.py

# 指定配置文件 / 端口
python app.py --config config.json --port 8000
```

## 配置说明（`config.json`）

> `config.json` 已在 `.gitignore` 中，**不会提交到仓库**（含你的真实序列号与 Access Code）。请基于随仓库提交的 `config.example.json` 生成你自己的 `config.json`，详见上方「首次初始化配置」。

```json
{
  "host": "0.0.0.0",
  "port": 8000,
  "webhook_url": "https://qyapi.weixin.qq.com/...",
  "allowed_ips": ["192.168.1.26"],
  "machines": [
    {
      "name": "机器1",
      "label": "01",
      "ip": "192.168.1.32",
      "serial": "01P00C510801320",
      "access_code": "18549249"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `host` | HTTP 监听地址，默认 `0.0.0.0`（监听所有网卡） |
| `port` | HTTP 端口，默认 `8000`，可用 `--port` 覆盖 |
| `webhook_url` | 企业微信群机器人地址；留空则不推送通知 |
| `notify_skip_filament` | 换料静默开关，默认 `true`；开启后换料期间不推送任何消息 |
| `notify_filament_silence_min` | 换料静默窗口（分钟），默认 `30`；命中一次换料提示即重新计时 |
| `notify_filament_keywords` | 可选，自定义「换料类提示」的关键词列表，覆盖内置默认值 |
| `allowed_ips` | 可「编辑」的客户端 IP 白名单；覆盖代码内默认值 |
| `machines[].name` | 机器显示名（与看板一一对应） |
| `machines[].label` | 机器短标签（如 `01`） |
| `machines[].ip` | 打印机局域网 IP |
| `machines[].serial` | 打印机序列号（MQTT topic 用） |
| `machines[].access_code` | 局域网 Access Code（打印机设置 → 局域网模式中获取） |

> 未配置或填错的机器在界面显示「未配置 / 未连接」，不影响其它机器。

配置修改后**重启服务**即可生效。

## 使用指南

1. **添加文件**：点击右上角「＋ 添加文件」，填写状态 / 机器 / 数量 / 备注。
2. **推进状态**：点击卡片上的 `打印中 ▶` 按钮一键往后推一档。
3. **拖拽改状态**：在「待打印 / 打印中 / 待摆盘填表 / 需改进重打 / 已完成 / 已放弃」六列之间拖动卡片改变状态（需在编辑 IP 下）。
4. **搜索**：在搜索框输入文件名 / 备注 / 机器；失焦或回车才计算；命中 1 个时全量显示并高亮跳动。
5. **归档查看**：「已完成」文件一键归档，在侧栏归档区点击查看详情。
6. **数据快照（自动备份回退）**：侧栏「数据快照」显示当前已有快照数，点击「查看 / 恢复快照」打开弹窗——左侧为按时间排列的快照列表（含每版条数与状态分布），右侧为**和主界面一致的只读看板预览**；选中某一版后点「恢复此快照」即可回退（需确认，且恢复前当前数据会自动轮转为新快照，可再次回退）。快照由后端在**每次写盘时自动生成**，无需手动操作。
7. **备份 / 恢复**：页脚「导出备份」下载 JSON；「导入恢复」从备份回灌。
8. **清空**：页脚「清空全部」会清空所有进度（不可恢复，需确认）。

## 状态流转

```
待打印 ──▶ 打印中 ──▶ 待摆盘填表 ──▶ 已完成 ──▶ 归档
                 ▲                    
  需改进重打 ────┘（回退重打，回到打印中）
                 
已放弃（终态，无后续流转）
```

| 看板列 | 默认高度 | 说明 |
| --- | --- | --- |
| 待打印 | 450px | 等待上机的文件 |
| 待摆盘填表 | 450px | 打印完待摆盘并填写信息 |
| 打印中 | 300px | 打印机正在打印 |
| 需改进重打 | 300px | 质量不达标，需重打 |
| 已完成 | 300px | 已打印完成 |
| 已放弃 | 300px | 放弃，终态 |
| 归档（侧栏） | — | 已完成后的归档，弹窗查看 |

## API 参考

基础地址：`http://<host>:<port>`。所有写接口（`POST / PUT / DELETE`）需**编辑 IP**，否则返回 `403`。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/` , `/index.html` | 返回仪表盘页面 | 公开 |
| GET | `/api/data` | 返回 `{machines, jobs, serverTime, canEdit}` | 公开 |
| GET | `/api/jobs` | 返回全部文件进度 | 公开 |
| GET | `/api/machines` | 返回各打印机实时状态 | 公开 |
| GET | `/api/ping` | 健康检查 | 公开 |
| POST | `/api/jobs` | 新建文件进度 | 编辑 |
| POST | `/api/jobs/{id}/next` | 推进某文件到下一状态 | 编辑 |
| POST | `/api/jobs/reorder` | 按 `ordered_ids` 重排（列表外 job 保留，不删除） | 编辑 |
| PUT | `/api/jobs/{id}` | 更新某文件字段 | 编辑 |
| DELETE | `/api/jobs` | 清空全部 | 编辑 |
| DELETE | `/api/jobs/{id}` | 删除某文件 | 编辑 |
| GET | `/api/backups` | 列出自动历史快照（名称 / 时间 / 大小 / 条数 / 状态分布） | 公开 |
| GET | `/api/backups/{name}` | 读取某快照完整数据用于预览（`{jobs:[...]}`） | 公开 |
| POST | `/api/backups/restore` | 恢复某快照（`{name}`）；恢复前当前数据自动轮转为新快照 | 编辑 |

> **数据安全**：`/api/jobs/reorder` 采用「保留列表外 job」策略，绝不会因拖拽而误删文件；后端每次写盘自动保留最近 **5** 份 `files.json.bak1~5`，意外覆盖可在「数据快照」弹窗中一键恢复（恢复前亦自动留档，可反复回退）。快照文件名仅允许 `[A-Za-z0-9._-]`，避免路径穿越。

## 访问控制与安全

- 默认仅 `ALLOWED_IPS = ["192.168.1.26"]` 可编辑，其它 IP 仅可查看（`/api/data` 返回 `canEdit:false`，前端自动禁用编辑控件）。
- 客户端 IP 解析优先级：**`X-Real-IP` → `X-Forwarded-For` → 直连地址**。
  - 经 Nginx 反代时，请用 `X-Real-IP`（由 `$remote_addr` 填，不可伪造），不要信任可被伪造的 `X-Forwarded-For`。
  - Nginx 示例：

    ```nginx
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    ```

> ⚠️ 若改动了 `app.py`，必须**重启后端进程**才能让修改生效（前端可 `Ctrl+F5` 强刷）。

## 通知（企业微信）

在 `config.json` 填入 `webhook_url` 后启用。每台打印机会在以下事件各推送一次（带去重，避免重复打扰）：

1. **✅ 打印完成**：进入「已完成」状态（同一轮打印只推一次，不会因状态抖动重复推）。
2. **⏰ 即将完成**：状态为「打印中」且剩余 ≤ 10 分钟（含 3 分钟防抖，跳过刚启动时的脏读数）。
3. **⚠️ 打印出错**：出现错误并带有明确错误原因（按错误文案去重）。

### 换料静默

换料（外挂料盘换料丝 / AMS 换料 / 打印结束后的退料）期间，打印机会连续上报一长串**提示型**错误：

```
请将外挂料盘的料丝拉出，并需要检测是否有料丝断在工具头（如用AMS请在换料后放管）
请将料丝插入进料口，直到料不断为止
换料失败，老料已拔出成功，请重新加载耗材
```

这些提示的错误码会随换料步骤不断变化、随后又被清除，去重标记挡不住，一次换料就能刷出十几条推送。
因此本工具内置**换料静默**：错误文案命中换料关键词（`料丝 / 换料 / 进料 / 退料 / 送料 / 出料 / 料盘 / 料线 / 耗材 / 断料 / AMS`）后，
对该机器开启一段静默窗口（默认 30 分钟，每命中一次重新计时），窗口内**任何推送都不发**（出错告警 / 即将完成 / 打印完成），只写日志：

```
机器1: 检测到换料提示，开始静默 30 分钟内的所有推送（换料期间不打扰）| 请将外挂料盘的料丝拉出…
机器1: 已恢复稳定打印，换料静默结束（本轮静默拦截 7 条推送）
```

- **静默结束条件**：打印机恢复稳定打印（连续「打印中」满 60 秒）→ 立即恢复推送；或到达静默窗口上限 → 自动结束。
- **真实故障不丢**：静默期内出现**非换料类**故障（如前盖脱落）不会即时推送，但静默结束后若该故障仍在，会补推一次。
- 无需推送换料消息时（例如改用 AMS 自动换料）：把 `notify_skip_filament` 设为 `false` 即可恢复原始行为。

## 已知限制与注意事项

- **单 MQTT 客户端限制**：每台拓竹打印机同一时间只允许 1 个 MQTT 客户端。服务运行期间，请勿用 Bambu Studio / 手机 App 连同一台打印机，否则会互相踢线。
- **周期 pushall**：空闲打印机可能只发心跳，服务默认每 60 秒向每台重发一次 `pushall`，确保状态持续刷新。
- **防火墙**：同局域网其它设备访问需在「专用网络」放行 `8000` 端口（本机访问不受影响）。
- **数据持久化范围**：仅「文件进度」落盘（`data/files.json`）；打印机实时状态仅在内存，重启服务后重新订阅获取。
- **开机自启**：把 `run.bat` 放入系统「启动」文件夹或用任务计划程序配置。

## 迁移到新设备

1. 复制整个 `printsync/` 文件夹到目标机任意位置。
2. 确认目标机已装 Python 3.10+ 且 `paho-mqtt` 可用。
3. 编辑 `config.json`，填入新网络环境下能访问到的打印机参数。
4. 双击 `run.bat`（或 `python app.py`）启动，用局域网地址打开网页。
5. 如需迁移历史进度，在原机「导出备份」，再在新机「导入恢复」。
